# 2.1 requests from the AI providers area

The AI code compiles and runs without this request: it looks the tier up by name
(`ModelRouter.ULTRA_CHEAP` / `ModelRouter.ultraCheapTier`), so until it lands OpenRouter simply
has no Ultra-cheap button and the preset is unreachable from Settings. Once it lands, Ultra-cheap
appears in the tier picker for OpenRouter only, and becomes the default when a user switches to
an OpenRouter key.

## 1. `data/remote/ModelPolicy.kt`: add the Ultra-cheap tier (required for the feature)

Add a first entry to `enum class CostTier` (first so the picker reads cheapest to dearest;
`ModelRouter.tiersFor` also sorts it first, so position is not load-bearing). Settings store the
tier by name (`enumOr(p[K.tier], CostTier.BALANCED)`), so no migration is needed, and nothing
outside `data/ai` does an exhaustive `when` on `CostTier`.

```kotlin
enum class CostTier(val label: String, val blurb: String) {
    ULTRA_CHEAP(
        "Ultra-cheap",
        "Open models for photos and labels, a small Claude for the coach and plans, with zero data " +
            "retention enforced. Only offered where Forge has a researched preset (OpenRouter)."
    ),
    ECONOMY(
        ...unchanged...
```

On providers without a preset, `ModelRouter` routes ULTRA_CHEAP exactly like ECONOMY
(`tierOf(ULTRA_CHEAP) == ModelTier.ECONOMY`), so `modelFor` and `roughMonthly` keep working.
