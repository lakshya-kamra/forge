# 2.1 requests from the Progress-photos area

Forge no longer stores progress photos. Everything in this area compiles and works without
the changes below; they wire the new behaviour into screens other areas own.

## 1. Nav host: deep link + optional callbacks for Progress (owner: Design & shell / integrator)

`ForgeNavHost.kt`, replace the Progress destination:

```kotlin
// was: composable(Routes.PROGRESS) { ProgressScreen(onBack = back) }
composable(
    Routes.PROGRESS,
    deepLinks = listOf(navDeepLink { uriPattern = DeepLinks.PROGRESS })
) { entry ->
    ProgressScreen(
        onBack = back,
        // Only the monthly progress-photo reminder deep-links here, so a deep-link launch
        // opens the Photos tab.
        startOnPhotos = entry.arguments?.containsKey(NavController.KEY_DEEP_LINK_INTENT) == true,
        onOpenAiSetup = { nav.navigate(Routes.SETTINGS_AI) },
        onOpenProfile = { nav.navigate(Routes.SETTINGS_PROFILE) }
    )
}
```

Needs `import androidx.navigation.NavController` (`navDeepLink` and `DeepLinks` are already
imported). `DeepLinks.PROGRESS = "forge://progress/photos"` is in `data/reminders/DeepLinks.kt`.
The three new parameters are optional with defaults, so the current call keeps compiling.
`onOpenProfile` is used when the photo estimate is waiting on a fresh eating screen
(Guardrails' 12-week rule): Profile settings is where the screen is re-answered.

## 2. Settings > Reminders: the monthly progress-photo toggle (owner: Tools, widgets, data)

New settings field `ForgeSettings.progressPhotoReminder` + `SettingsStore.setProgressPhotoReminder(v)`
(key `reminder_progress_photos`). Unset reads as **on** for anyone with `onboardingVersion >= 2`,
off otherwise. Scheduling is already handled: `ReminderScheduler.start` now also keeps
`ProgressPhotoReminder` (first Sunday of each month, 08:00, deep link to Progress) in step with
the toggle, so the settings screen only flips the value.

Please add a row to the Reminders section of `DataSettingsScreen.kt` (+ VM), for example:

```kotlin
// DataSettingsViewModel
fun setProgressPhotoReminder(on: Boolean) = viewModelScope.launch {
    repo.settingsStore.setProgressPhotoReminder(on)
}

// DataSettingsScreen, after the ReminderType rows
SwitchRow / ListItem(
    title = "Monthly progress photos",
    subtitle = "First Sunday of each month, 8 am - front, side, back",
    checked = state.settings.progressPhotoReminder,
    onCheckedChange = vm::setProgressPhotoReminder
)
```

Do **not** add it to `ReminderType`: that enum is switched over exhaustively in
`DataSettingsScreen`/`DataSettingsViewModel`, which is why the photo reminder is its own
object (`data/reminders/ProgressPhotoReminder.kt`, notification id 4104, unique work
`forge_reminder_progress_photos`). The same Progress screen also has the toggle on its Photos
tab, so the feature is usable before this lands. If the "any reminder on" summary in that
screen should count it, include `ProgressPhotoReminder.isEnabled(state.settings)`.

## 3. Backup / JSON export (owner: Tools, widgets, data) - check only

- If the JSON export writes every settings field, add `progressPhotoReminder`.
- `progress_photo` rows still exist for users upgrading from v2.0 until they tap "Delete from
  Forge" on the Progress screen. The export already leaves photos out; nothing to change.
- Saved AI photo estimates are ordinary `body_measurement` rows with
  `bodyFatMethod = "VISUAL_AI"` and no tape sites, so they export/import as-is.

## 4. CONTRACTS.md privacy bullet (owner: integrator)

The quality-bar line "body/progress photos stay in app-private storage" is no longer true.
Suggested wording:

> Privacy: Forge never stores progress photos. People keep them in their own gallery; Compare
> reads them through the Photo Picker into memory only, and they are sent to an AI provider
> only after an explicit per-use consent on that screen, then discarded. Meal photos stay in
> app-private storage, excluded from backup.

## Notes (no change needed)

- No manifest changes: the Photo Picker needs no permission; saving to `Pictures/Forge Progress`
  uses MediaStore `RELATIVE_PATH` (Android 10+, no permission). Android 8-9 export through
  `OpenDocumentTree` instead, and the pose-guide camera button is hidden there.
- `ProgressPhotoFiles` now only finds and deletes v2.0 leftovers; its old `stage/commit/
  importPhoto/base64ForAnalysis` functions are gone (only this area used them).
- The `progress_photo` table and `BodyDao` photo queries are kept for the one-time migration
  card. Dropping the table can wait for a later schema version.
